It ran the stock image with no volume, so nothing of ours could be on it: our nine graphs are baked into our image, the models and plates come from the volume, and Binc's tree holds no ComfyUI workflow files at all (`20_STEREO`/`10_CORROSION` are shot folders, `ComfyUI-Shared` is input, models and output).

Volume id, datacenter, image and credential are in the saved configuration, so the next pod from the app boots our image on the volume.
- The empty stock-image pod (`Live-Proof`) was stopped; it bills nothing stopped.
- **Default Configuration and per-pod configurations** (branch `feature/registry-and-volume`). The gear panel is now the Default Configuration. The create form has an Override configuration button that opens the same panel for the new pod, started from the default, and sends that configuration with the request (`config`); the card has a Configuration button that shows a pod's own configuration, changes it or puts it back on the default, applied when the pod is recreated. The core keeps per-pod configurations in `pod-configs.json`, uses them for Recreate, drops them on delete; the RunPod key, "apply by default" and no-spend mode stay app-wide. The deprecated Python API has no endpoints for this; the Electron app is the path.

The token comes from `GITLAB_TOKEN` or the stored `docker login`.
- **Workflows are mounted, not baked** (Lucas: "ideally they're mounted"). The image links ComfyUI's Workflows panel to `/workspace/comfy-shared/workflows` on the volume and copies the repo's nine graphs in only while that folder is empty, so a pod's workflows change without a rebuild and survive the pod; `./start.sh sync` copies `apps/comfy-app/workflows/` there (key `workflows`). On the Mac the panel keeps reading the repo folder through the link `setup.sh` makes.

While a pod is starting the list polls every 5 seconds so the card follows it; Resume kicks that off.
- The deprecated Python API crashed on a stopped pod (`runtime` is null), which is why the app said "no pods" after the proof; fixed, and it gained the details and logs endpoints for browser mode.
- `./start.sh e2e-live` with `RUNPOD_LIVE_KEEP=1` leaves the proof pod stopped instead of deleting it, to look at in the app; stopped with no per-pod volume it bills nothing.
- **Pause all** in the navbar stops every running pod at once. Stop is RunPod's pause: the pod keeps its disk and bills storage only; Delete terminates it and nothing bills.

### No-spend mode, the RunPod key in the panel, the app driven through Electron, the live proof (branch `feature/no-spend-mode`)
- **No-spend mode**: a switch in Configuration (or `RUNPOD_DRY_RUN=1`) makes the core simulate pods with the shape the dashboard shows for real ones, so every screen, action and test runs the same way and nothing reaches RunPod or bills. The navbar says so while it is on.
- **The RunPod API key** is entered in the Configuration panel, first section. The core stores it in `~/.config/runpod-pod-manager/.env`, the file the Electron shell and the Python backend already read, puts it in the running process so the next call uses it, and shows only its last four characters afterwards. The deprecated Python API got the same two endpoints for browser mode.
- **The app driven by Playwright through Electron** (`./start.sh e2e-app`): the real app with its own config folder, no Python, the page talking to the core over IPC; the whole pod lifecycle in no-spend mode and a configuration save. **The live proof** (`./start.sh e2e-live`, `RUNPOD_LIVE=1`): one real pod with the stock image, seen running with its ComfyUI URL, stopped and deleted by the test itself.

- The comfy-app image `comfy-app:contract-v26` was built for linux/amd64 on this Mac (4.94 GB, through emulation). The push waits on `docker login` and Binc's yes; `build.sh --push` does the rest (branch `feature/comfy-app-image-push`).
