### Sync progress that is true; parallel streams; skip the renders (branch `worktree-agent-…`, merged at `b977c9e`)
- Lucas: "after the first project folder loads (1/3) the whole thing seems to restart"; "real sync still always says folder 1 of 3"; "i need an accurate progress bar"; "Parallel rsync streams over SSH do this"; "make the number of parallel uploads configurable in settings". The cause: this Mac's rsync is Apple's openrsync, whose `--progress` reports each file from 0 to 100 percent, and the card mapped every file's percent onto the folder's bar; the first folder is the project tree, so "1 of 3" was true for hours while the bar restarted on every frame.
- Now: a bounded `rsync -n --stats` listing pass per folder before any copy gives each folder's file and byte totals and the run's; the measure is files started plus rsync complaints over the folder's total ("project (1 of 3) · file 1,240 of 24,220 · 1,238 ok · 2 errors · 12.4 GB of 81.0 GB · 2.3 MB/s · ~9 h left"); bytes summed across streams on both rsyncs and the AWS CLI; progress events at most four a second; rsync exit codes 23 and 24 are warnings and the next folder always starts. One state reducer (`src/sync-progress.js`) feeds the store, the card and the modal; the modal keeps the last 500 files and 2,000 lines instead of re-rendering everything on every line, and uses the modal's own footer (the doubled buttons under the custom row are gone).
- **Parallel streams**: a push over SSH splits each folder into its top-level entries and runs up to `sync_parallel` rsync processes at once (Default Configuration, Options: "Parallel uploads", default 4, 1 to 16). Measured on this Mac: 1.5 MB/s to the internet, 1.2 MB/s over SSH to the pod, so streams keep the line full on the thousands of small files but cannot beat it.
- **Skip the shots' existing renders**: the 24,220 files in the push are real, 20,300 of them DPX frames under the shots' `06_REVIEW` folders, 86.7 GB in all, which the pod never reads. A switch in the confirmation, on by default, excludes `05_TEMPS`, `06_REVIEW` and `07_DELIVER` and the confirmation shows both figures: 4,564 files and 17.5 GB without the renders. Pull is what brings renders back. ADR-007's option C, built as a switch.

### Pod defaults, idle stop, volume sync, dev mode (branch `feature/runpod-defaults-idle-stop-sync`)

- Idle stop: `apps/runpod-api/idle.py` probes each watched pod's ComfyUI through RunPod's proxy once a minute and stops it after N quiet minutes (default 30, set in Configuration or per pod). The proxy URLs are RunPod's real ones.
- `infra/scripts/sync_volume.py` (`./start.sh sync --pod <id>`) copies the mapped folders to a pod's network volume over rsync, never deletes, and copies plates only with `--plates --approved-by <name>`.

Pod creation and the launcher refuse to run without a required folder.
