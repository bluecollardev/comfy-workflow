## What was found

- **Binc's paths are declared, not configurable.** The structure master
  (`00_POLICY/structure_v003.md`) opens with one absolute root and makes
  everything under it relative; the root in use is revision three of the tree.
  On disk that root is literal in 340 graphs (7,599 mentions) and in every
  job file, and most scripts hardcode it. The systems page says how to cope:
  containers and the Mac link the same path, so a graph runs unchanged
  anywhere. That rule is what the mount configuration implements.
- **The tree is largely AI-written, under human rules.** 149 scripts and 19
  pack versions in nine days; 16 scripts still carry Claude sandbox paths;
  seven `claude/*.md` briefs are cited by the policy pages. The rules
  themselves are Binc's, versioned, one page each, and nothing in Binc's
  prompts asks an agent to write code: the operator brief forbids it.
- **The pod defaults could not have worked and would have cost money.** The
  API sent a GPU id RunPod does not know, booted an image with no packs that
  ignores the links, asked for a per-pod volume beside the network volume, and
  had nothing to stop a forgotten pod. Fixed on a branch, below.
- **Two things that looked done were not:** the library toast orchestrator
  rendered every toast hidden, and the pod form sent the stock image whatever
  was chosen. Both found by driving the real page and fixed.

## The browser suite, run before the port

Lucas: "maybe if this is working we should test it first." The dashboard has
a Playwright suite (`apps/runpod-dashboard/e2e`, 35 specs, an in-memory fake
of the API mounted with `page.route`, no backend or key needed). First run of
the day: 25 passed, 9 failed. Two causes:

- **A bug of mine from the toast work.** `toast.run` returned the action's
  value, and a void action returns nothing, which every caller read as
  failure: after a successful delete, remove or create the list never
  refreshed and the form never collapsed. Fixed: `run` returns an outcome
  object, a void action is a success. Five callers updated. The suite caught
  what the browser check of one path had not.
- **Specs behind the day's changes:** the stock image, a 50 GB per-pod volume
  and the on-demand cloud as defaults, a GPU menu with an H100, OAuth notices
  as inline alerts. The specs now expect the configured image, 0 GB, the
  community cloud, the small-card menu and the toasts, and the fake API
  serves the mount configuration and the GPU menu.

End of day: 35 passed. The suite is the safety net for the TypeScript port:
every step must keep it green, and the fake API is the contract the IPC
bridge will have to honour.

## State management

`toast`) and otherwise in component refs passed down as props, with the
dashboard list refetched by whoever changed it. Lucas asked that it use
proper state management; Pinia is adopted, with stores for ui, toasts, pods

the change, which also gives the IPC bridge one place to plug into.

## Decided

`docs/ADR-005-typescript-core-no-server.md`: the pod manager becomes a
TypeScript core inside Electron, called over IPC, with HTTP as an optional
adapter and the MCP server and CLI importing the same core. No separate
server to boot, no Python to install per PC. Python stays for ComfyUI, the
packs and Binc's scripts. Done on `feature/ts-core`, stacked on the branch above: the core in
TypeScript inside the app (`apps/runpod-dashboard/libs/core`), mounts, gpus,
governance, idle and pods against RunPod's GraphQL API, 22 Vitest tests, and
Electron exposing it to the page over IPC with the renderer routing there when
inside Electron and to HTTP otherwise. The smoke boot calls the core from the
page: the GPU menu and the mount configuration come back over IPC. Nothing in
the UI needs Python: what is left on the Python side is git accounts,
repositories, image env, OAuth and the MCP server, and the Electron app still
starts that backend until they are ported.
