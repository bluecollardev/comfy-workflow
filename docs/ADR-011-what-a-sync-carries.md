# ADR-011: What a sync carries, and what it does with what is already there

Status: accepted, 2026-10-25. Builds on ADR-007 (the volume as the hub; additive, never deletes).

## Context
A push of this PC's folders was all or nothing: all of ComfyUI-Shared, including `output/` (what pods write), and the whole project tree. On the real CANALV2 that is 23,547 files and 86.7 GB, of which 63 GB is the shots' `06_REVIEW` renders and 14 GB is Binc's `80_TEST-BUCKET` (quick tests for his timeline, `00_POLICY/project_v002.md`). Lucas asked to exclude output, to choose among the ComfyUI-Shared folders per pod and in the default (with separate rows for Push and Pull), to skip the renders and the test bucket by default, and to skip files that are already on the pod, or replace them, as chosen.

## Decision

### 1. Which ComfyUI-Shared folders (configuration)
- `sync_shared` (push; default `input, models, workflows`: not `output`) and `pull_shared` (pull; default `output`), checkboxes in Default Configuration > Folders on this PC and in a pod's own configuration (the pod's wins). Two rows, Push and Pull, separated by a dotted rule.
- The Sync window starts from the effective choice and may change it for one run (`shared` on the request; MCP `sync.shared`; CLI `--shared a,b`).
- Unchosen folders are excluded with an anchored pattern (`/output/`): the top level of ComfyUI-Shared only, so an `output` folder deeper down still goes. The `workflows` step (the repo's graphs) goes with `workflows`. The S3 transport gets the equivalent excludes.
- Pull steps for output keep the key `output`; other folders are `shared/<dir>`. Each shot's review and deliver folders are unaffected.
- `sync_parallel` (rsync streams at a time) defaults to 8 for new configurations; a saved value is kept.

### 2. What to leave behind on a push (Sync window, per run)
Two switches, both on by default; the file and byte count in the confirmation follows them (from the listing passes):
- `skip_renders`: `05_TEMPS/ 06_REVIEW/ 07_DELIVER/` at any depth. Pull is what brings renders back.
- `skip_tests`: `/80_TEST-BUCKET/`, top level of the project only. No shot's graph reads it.
On the real tree: 23,547 files / 86.7 GB all; 4,564 / 17.5 GB without renders; 1,361 / 2.4 GB without renders and the test bucket (checked with `rsync -n`).

### 3. A file that is already on the pod (`existing`, SSH only)
| Choice | rsync flag | Sends | Misses |
|---|---|---|---|
| `update` (default) | none | a file whose size or time differs | nothing; resends a file whose time differs but whose content is identical |
| `size` | `--size-only` | a file whose size differs | a same-size edit |
| `checksum` | `--checksum` | a file whose content differs | nothing; reads every file at both ends, so it is slow |
| `replace` | `--ignore-times` | everything again | nothing |
The S3 transport uses `aws s3 cp`, which has no such choice. Nothing is ever deleted, in any mode.

**Skipped** is shown beside copied and errors: the files in scope less the files the chosen rule would send. Scope comes from a second dry-run listing with `--ignore-times` (every file counts as to-send), so it is exact and costs one more listing per folder; the confirmation and the running view use the same figure.

## Consequences
- A first push is about 16 GB instead of 87 GB; later pushes send only what changed.
- Existing saved configurations pick up the defaults for the new keys (`pull_shared`); `sync_parallel` stays as saved.
- The CLI has `--shared`, `--skip-renders`, `--skip-tests` and `--existing`; the MCP `sync` tool has `shared`, `skip_renders`, `skip_tests` and `existing`. Defaults there are off (the app's switches default on), so a script says what it means.
- Not run against a live pod: the flags and excludes were checked with real local rsync runs and the app in no-spend mode.

## Update 2026-11-03: `temp/` is never carried

A push of ComfyUI-Shared always excludes its top-level `/temp/` (scratch, and the staged Panama rounds in `temp/rounds/`), whatever folders are chosen. It is not one of the choosable folders. See ADR-021.

## Amendment: Push order, preflight and a full volume (2026-11-18)

**What happened.** A manual Sync push sent the whole project tree (2.1 TB on the BKU1 drive) to a 1,000 GB volume. 15,134 files went up, then every stream stopped with "Disk quota exceeded". The graphs step (`comfy-shared/workflows`) came after the project step, so `mono_v015` and `retime_v014` never landed. Separately, the "workflows" step read `apps/comfy-app/workflows` of the repo, which does not exist in the installed app (no repo beside it), so that step failed every time.

**What a push does now** (`libs/core/src/sync.ts`, `syncrun.ts`):
1. **Order.** The RUN order of a push is: workflows (the graphs), then comfy-shared (input, models, output, workflows per `sync_shared`), then the project, then the plates: the small and important first, so a later failure (a full volume) never costs the graphs. The plan event and the panel keep their own order for display.
2. **Where the graphs come from.** The repo's `apps/comfy-app/workflows` when that folder exists; else the mapped local `ComfyUI-Shared/workflows` (then the comfy-shared step leaves `workflows/` out, so the folder goes once, not twice); else the step is skipped with the warning "No local workflows folder: the graphs step was skipped". A step whose local folder is not mapped or does not exist is a warning event (`kind: 'warning', code: 'skipped', key, reason, text`) and the run continues; a missing source never fails a run.
3. **Preflight, before any byte moves.** The listing passes already count the push; nothing copies until the totals exist. The totals are compared with the volume: its size from RunPod's record (GB as RunPod counts them) and, when the pod answers over SSH, the real free space from `df -Pk` of the mount (10 seconds at most, best effort). If the push is bigger than the free space (or, when free is unknown, than the volume) it is REFUSED with a 400 (`code: 'over_capacity'`) before copying: "This push would send 2.1 TB; the volume is 1,000 GB (about 340 GB free). Nothing was copied. By step: workflows 1 MB, comfy-shared 12 GB, project 2.1 TB. Push only the graphs (untick the project), or enlarge the volume." There is no override: the person fixes the selection or the volume. The `totals` event carries `capacity_bytes`, `free_bytes` (null when unknown) and `over_capacity`; a push that fits but leaves under 5% free carries a warning event. `count()` (the confirmation's totals call) returns the same three fields on `all` and on `without_renders`, each worked out for its own count, so the Sync window can show the alert before the run; a failing lookup gives null and false and never fails the count. A pull, a `paths` run, the simulated run and the S3 transport (which has no cheap count) have no preflight.
4. **A full disk stops everything.** When any stream's output contains "Disk quota exceeded", "No space left on device" or "ENOSPC", every remaining stream is aborted at once (not 15,000 failures) and the run ends as failed with `code: 'volume_full'` (a push) or `'disk_full'` (a pull that fills this PC's disk) and the message "The volume is full (Disk quota exceeded). N files were written. Not done: <steps>. Free space or enlarge the volume, then run again." The error event carries `code`, `text` and `not_done` (the step keys not started or unfinished); the History entry says so with files and bytes, the sync run log gets the same line, and an Auto sync pull shows it as its error item.

**Tests** (`libs/core/tests/syncguard.test.ts`, fakes only): the order, the graphs-source chain and the skip warning, a missing source of any step, the refusal with sizes that copies nothing, `df` versus capacity, the 5% warning, `count()` fields per variant, and the disk-full abort, message, code, History and log, for a push and a pull.

## Leaving folders out (amendment 2026-11-18)

Binc needs to leave CANALV2, which is massive, out of a push. A push now takes patterns to leave out: the configuration's `sync_exclude` (a list, default empty, in the Default Configuration and in a pod's own configuration; the pod's own list replaces the default's; export, import with backup and undo, reset and Recreate carry it) plus the run's own `exclude` (`SyncRequest.exclude`, the `sync` MCP tool's `exclude`).
- **Patterns** are rsync's, relative to EACH step's local root: a leading `/` anchors to the root (`/CANALV2/` is only the top-level one), a trailing `/` means folders only (`CANALV2/` is every folder of that name), otherwise it matches at any depth (`*.tmp`). A pattern is trimmed, not empty, at most 200 characters, at most 100 patterns, with no NUL or line break, no `..` segment and no leading `~` (a 400 naming the field). Patterns reach rsync as separate array arguments (no shell: a name with spaces, quotes or `;` is data) and, over the S3 transport, as `--exclude` globs (`sync.s3Glob`: `X/` becomes `X/*` and `*/X/*`, `/X/` becomes `X/*`, a plain `X` becomes `X`, `*/X` and what is under it).
- **By default they only remove things from a push, and nothing on the volume is deleted** (there is no `--delete-excluded` and no `--delete` anywhere; a test asserts it). A folder already on the volume stays there unless the person asks for the removal below. A pattern that removes a step's whole content sends nothing for it.
- **Totals follow them.** The listing pass, the confirmation's `count()` (both variants) and the preflight use the same excludes, so the per-step sizes and `over_capacity` reflect them: the incident's 2.1 TB project tree with `CANALV2/` left out is 10 GB in the test and fits the 1,000 GB volume. The History entry records how many patterns were left out and the first few.
- **Choosing.** `sync.folders({ pod_id })` lists the top-level directories of each push step's local root (one `readdir`, dotfiles, symlinks and what a sync never carries hidden, sorted, at most 500) and `sync.measure({ pod_id, step, name })` sizes one on demand (`du -sk` spawned with an argument array, 120 s, cached 5 minutes, cancellable with `sync.measureCancel(id)`); the name must be a direct child directory of the step's root (no slash, no `..`, no symlink out). MCP: `sync_folders`.

### Per-folder defaults (amendment 2026-11-18)
`folder_excludes` (`{ project, plates, comfy-shared, workflows: [patterns] }`, default `{}`) sits next to the flat `sync_exclude`, in the Default Configuration and in a pod's own configuration (normalise, validate with a 400 naming the folder and the bad pattern, at most 100 per key and 300 in all, unknown keys dropped; export, import with undo, reset and Recreate carry it). Patterns are relative to THAT step's root and have the same semantics. **The merge:** a pod's own map replaces the Default's per key; a key the pod lacks falls back to the Default's; an empty list in the pod clears that key for the pod. **A step's effective list** = the global `sync_exclude` (the pod's, else the Default's) UNION that step's `folder_excludes` UNION the request's `exclude`; a pattern saved for project never reaches comfy-shared. It feeds the rsync and S3 arguments, `count()`, the preflight, the removal below and the History count. `sync.folders()` returns per step `saved` (the effective saved patterns, de-duplicated) and `saved_sources` (`default`, `pod` or `folder`), and `supports` (`exclude`, `delete_excluded`, `folder_excludes`, `measure`) so the window can hide what an older core lacks.

### Removing what was left out, from the volume (amendment 2026-11-18)
Binc wants a push with exclusions to also clear what an earlier push already put on the volume (the half-copied CANALV2 project tree of the failed push), so the volume does not have to be reloaded. **rsync `--delete-excluded` is NOT used**: it implies `--delete`, so it would also remove every file on the volume that is not in the local tree (the renders and outputs the pods made, which must be kept). The incident: a 2.1 TB project tree was half-copied to a 1 TB volume. Instead, `delete_excluded` (a `SyncRequest` option, default the configuration's `sync_exclude_delete`, default false) runs a TARGETED, GUARDED removal before the copy (`libs/core/src/syncdelete.ts`):
- **Candidates** are listed on the volume side per step (SSH: one bounded `find` under the step's remote root; S3: a bounded level-by-level listing) and matched in TypeScript with the SAME pattern semantics as the exclude; no pattern text reaches a shell. Only the outermost matched folders are removed, whole.
- **Guards:** strictly inside the step's remote root (never the root, never `..`, never a symlink, and on the pod `readlink -f` must lie inside the real root or the removal is refused), never `.journal`, a shot's render folders (05_TEMPS, 06_REVIEW, 07_DELIVER) are not removed on their own unless a pattern names them (inside a folder removed whole they go with it), at most 50,000 matches and at most 20 matches among a root's direct children per pattern ("that pattern is too broad: <n> folders"). The command is one `rm -rf --one-file-system -- "<resolved path>"` per matched folder (or one `aws s3 rm --recursive`), quoted, never a glob, sequential, abortable, 30 minutes each.
- **Preview and consent:** `count()` returns `would_delete: [{ step, path, bytes, files }]` and `would_delete_bytes` whenever `delete_excluded` is on (an empty array and 0 when nothing matches, never omitted); the run needs `approved_by` (400 "Deleting from the volume needs the name of who says yes") when anything would be removed; a pull or a files list refuses it.
- **Order:** the preflight counts the free space AFTER the removal (`free + would_delete_bytes`) for `over_capacity`, then each folder is removed with `delete` events (`removing`, `removed`, `failed`), then the copy; a failed removal stops the run before any copy and names what was removed. The History entry records the folders and bytes removed, the first few, and the approver.
- Tests: `libs/core/tests/syncdelete.test.ts` (a fake volume holding renders and outputs that must stay untouched, the guards, the exact command arrays, S3, the named yes, the free space, a failed removal) and the per-folder cases in `syncexclude.test.ts`.

## Symlinks and mounted volumes (amendment 2026-11-19)
The folder picker and the sync walk met links: a project tree reached through a symlink, a tree on a mounted volume, a link to a 2 TB drive inside the tree. **The policy: a link is NEVER followed during a push walk** (following one is how a 2.1 TB tree fills a volume); **rsync copies a link as a link** (`-rlt`, never `-L`), **the S3 route skips links** (`--no-follow-symlinks` on a push, so both transports agree that a link's contents are not sent); and **a symlinked ROOT is followed, because it IS the folder the person chose** (the rsync source is `<root>/` with a trailing slash).
- **The picker** (`listDirs`) keeps the LOGICAL path: `path` and `parent` are the path you came by (after `~` and resolve), so Up goes back through the link; `real` is the realpath when it differs. A link to a folder has `link: true` and its `target`; a broken link and a link to a file are hidden. An unreadable folder is a 403 with `code: 'no_permission'` and, on macOS, a `hint` (System Settings > Privacy & Security > Files and Folders, or Full Disk Access).
- **Volumes** (`mounts.volumes`, MCP `list_dirs { volumes: true }`): macOS `/Volumes/*`, Linux `/media/<user>/*`, `/run/media/<user>/*`, `/mnt/*`, with `name`, `path`, `link` (macOS lists the boot volume as a link to `/`, sorted last), `target`, `size_bytes`, `free_bytes` and `readable`. Each `statfs` is raced against 3 seconds: a hung network mount is listed unreadable ("did not answer") and never blocks the list.
- **The sync folder list** follows a symlinked step root (`stat`, not `lstat`) and lists linked folders with `link`, `target` and the note "A link: copied as a link, its contents are not sent"; `measure()` of a link measures nothing (`{ bytes: 0, link: true, target }`).
- **The project-tree readers** (`declaredRoot`, `declaredPlates`, shot listing) follow a link to a folder with `isDirFollow` (stat; a broken link is not a folder), depth-bounded and loop-safe (a folder is entered once, by its realpath).
- **Warnings:** a push emits `{ kind: 'warning', code: 'symlink', key, path, target, text }` once per link: a linked step root (its contents ARE sent) and every top-level entry that is a link to a folder ("<name> is a link to <target>: it is copied as a link, not its contents", plus "(skipped on the S3 route)" there); at most 50, then "and N more links".
- Tests: `libs/core/tests/symlinks.test.ts`.
